WAF 部署说明
============

一、目录内容
  wafd         进程守护（唯一入口，托管 waf/admin/cron 三个子进程）
  waf          WAF 引擎（由 wafd 自动拉起，请勿单独启动）
  admin        后台管理（由 wafd 自动拉起，请勿单独启动）
  cron         定时任务（由 wafd 自动拉起，请勿单独启动）
  config/      配置文件（部署前必须检查 database.json / custom.json）
  web/         后台页面与静态资源
  sql/         建库脚本（init.sql，全新安装时自动导入）
  wafctl.sh    一键启停脚本
  部署说明.txt  本文件

二、部署步骤
  1. 解压到任意目录，如 /usr/local/waf
  2. 修改 config/database.json：填写 MySQL 地址、账号、密码（pwd 交付时留空，必须填写）
  3. 启动：./wafctl.sh start
     启动时会自动执行数据库初始化检查（admin -initdb）：
       - 连接失败：打印分步设置说明（MySQL 是否启动/账号权限/防火墙），按提示处理后重试
       - 空数据库：自动建库并导入 sql/init.sql，并提示默认管理员账号
       - 已初始化：直接跳过
     也可随时手动执行该检查：./wafctl.sh initdb
     存量升级：请勿对已有数据执行 init.sql，联系官方获取对应版本的升级 SQL
  4. 后台访问：http://服务器IP:后台端口（端口见 config/app.json 的 admin.http.addr）
     默认管理员账号 admin / admin123，首次登录后请立即修改密码
  5. config/custom.json 说明（交付时均留空）：
       admin_session_secret  后台会话加密密钥：留空即可，admin 首次启动自动生成随机密钥写回
       license_secret        实例签名密钥：留空即可，首次启动自动向云平台注册并颁发写回
                             （Pro 版激活使用授权码，在后台授权管理页操作，无需手工填写）
       platform_base_url     云平台对接地址：对接云平台时填写，为空则平台相关功能自动禁用

三、日常运维
  ./wafctl.sh status    查看三个进程状态（pid/运行时长/累计自动重启）
  ./wafctl.sh restart   全量重启三个子进程（wafd 进程不退出）
  ./wafctl.sh stop      停机（人为停机，子进程不会被自动拉起）
  ./wafctl.sh initdb    手动执行数据库初始化检查（连接排障/补导入）
  子进程崩溃会自动重启；10 分钟内反复崩溃 3 次及以上进入指数退避（上限 30 分钟），
  稳定运行 10 分钟后自动恢复正常重启间隔。
  启动失败判定：任一子进程连续 3 次启动后 10 秒内退出（典型原因：端口被占用、
  数据库不可达、配置错误），wafd 判定为不可恢复故障——直接停止全部进程并打印
  该子进程日志末尾，请按提示修复后重新 ./wafctl.sh start（不会无限重试空转）。

四、日志位置
  runtime/log/wafd/daemon.out.log   wafd 守护日志（子进程退出/重启/退避记录）
  runtime/log/wafd/<名称>.out.log   子进程控制台输出（含 panic 堆栈）
  runtime/log/engine|admin|cron/    各进程结构化业务日志

五、开机自启（可选，systemd 环境）
  创建 /etc/systemd/system/wafd.service（# 号注释行可保留，systemd 支持）：

  [Unit]
  # [Unit] 段：服务的基本信息与启动顺序
  Description=WAF Daemon (waf/admin/cron)
  # ↑ 服务描述，systemctl status 里显示的名字
  After=network-online.target mysqld.service mysql.service mariadb.service
  # ↑ 启动顺序：等网络就绪、数据库服务起来后再启动本服务；
  #   写多个名字没关系，系统只认本机真实存在的服务名，没有的自动忽略
  Wants=network-online.target
  # ↑ 弱依赖：希望网络 target 一起启动，但它起不来也不连累本服务

  [Service]
  # [Service] 段：进程怎么跑
  Type=simple
  # ↑ 进程模式：ExecStart 命令前台常驻、启动即算成功（wafd start 即前台阻塞命令）
  WorkingDirectory=/usr/local/waf
  # ↑ 工作目录 = 安装目录，wafd 靠当前目录找 config/web/runtime，
  #   写错或漏掉就找不到配置，必须改成本机真实路径
  ExecStart=/usr/local/waf/wafd start
  # ↑ 启动命令（必须绝对路径）
  Restart=always
  # ↑ 进程无论因何退出都自动拉起
  RestartSec=5
  # ↑ 每次拉起前等 5 秒，避免失败时疯狂重启刷日志
  LimitNOFILE=65535
  # ↑ 文件描述符上限：WAF 反代需撑大量并发连接，Linux 默认 1024 不够

  [Install]
  # [Install] 段：开机自启注册到哪
  WantedBy=multi-user.target
  # ↑ 相当于传统运行级别 3（多用户文本模式），enable 时在此级别注册自启

  启用：systemctl daemon-reload && systemctl enable --now wafd
  （systemd 守护 wafd，wafd 守护三个子进程，双保险）
  注意：服务托管后停止/重启一律用 systemctl stop/restart wafd；
  若保留 Restart=always，wafd stop 会被 systemd 立即拉起。

六、注意事项
  - 请勿手动启动 waf/admin/cron，一切通过 wafd 托管
  - 升级流程：./wafctl.sh stop → 覆盖二进制文件 → ./wafctl.sh start
  - wafd 控制通道仅监听 127.0.0.1（本机回环），无需在防火墙放行
  - 云安全组请勿放行 WAF 引擎高位端口（如 8081），仅放行业务 80/443 与后台端口
